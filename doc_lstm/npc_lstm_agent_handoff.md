# LSTM/心电分析模型训练交接说明

更新时间：2026-10-11

本文只给负责模型训练、模型结构选择和量化准备的 agent 使用。本文不要求了解 NPC 的 RTL、Wishbone、AM、UART、SoC 地址译码或 DiffTest 实现。

## 1. 训练阶段需要关注的目标

请围绕以下问题设计和记录模型：

- 输入是什么格式，单位和范围是什么；
- ADC 采样率是多少；
- 一次推理使用多少个连续样本；
- 模型结构是什么；
- LSTM 层数、输入维度、隐藏层维度和输出维度是多少；
- 输出表示什么，分类结果还是连续数值；
- 是否需要实时处理；
- 单次推理允许的延迟和内存占用大约是多少。

训练阶段先使用稳定、可复现的离线输入，不需要等待真实 ADC 接入。

## 2. 目标软件环境

最终软件环境是 RV32I 裸机程序：

~~~
-march=rv32i
-mabi=ilp32
~~~

模型软件需要避免浮点硬件、M/C/F/D/Zicsr 扩展、Linux、文件系统、动态运行时和大型标准库。训练过程可以使用浮点，但必须能够导出固定点版本。

## 3. 输入和输出规范

需要提供一份明确的数据说明，至少包括：

~~~
输入样本位宽
输入是否有符号
输入的物理单位
归一化范围
采样频率
每个窗口的样本数量
窗口是否重叠
特征维度
输出类别或数值范围
~~~

第一版建议提供固定测试向量：

~~~
输入文件或数组
期望输出
允许误差
输入长度
输出长度
~~~

输入不能只存在于训练脚本中，需要能够导出为 C 数组、二进制文件或明确的文本格式。

## 4. 模型结构记录

请记录完整的模型结构，不能只给网络名称。至少包括：

~~~
输入张量形状
每一层的类型
每一层的输入/输出形状
LSTM 层数
隐藏层维度
是否双向
是否使用 attention 或额外全连接层
输出层结构
每层参数数量
总参数数量
~~~

第一版建议优先考虑单向、固定长度、固定维度的模型。双向 LSTM、动态序列长度和复杂 attention 会增加硬件控制和存储复杂度，等基础链路跑通后再评估。

## 5. 定点化要求

训练 agent 需要给出浮点模型到定点模型的转换方案。至少需要确定：

~~~
权重位宽
偏置位宽
输入位宽
激活值位宽
累加器位宽
每个张量的小数位数量/Q 格式
右移规则
舍入规则
饱和规则
溢出行为
~~~

一个可讨论的起点是：

~~~
输入和权重：有符号 8 位或 16 位
乘加累加器：有符号 32 位
中间结果：明确右移和饱和
输出：固定宽度定点数
~~~

这只是候选方案，不是最终格式。浮点模型、主机端定点模型、RV32I 软件版本和未来 RTL 加速器必须使用同一套规则。

不要依赖 C 语言有符号溢出得到未定义结果。右移、截断、舍入、饱和和负数处理都要写成明确规则。

## 6. sigmoid 和 tanh

LSTM 通常需要 sigmoid 和 tanh。需要说明部署版本使用哪种近似：

~~~
查找表
分段线性函数
定点多项式
饱和区间直接取常数
其他近似
~~~

每种近似都要提供：

- 输入定点格式；
- 输出定点格式；
- 输入范围；
- 表格或系数；
- 舍入和饱和规则；
- 与浮点结果的最大误差。

训练 agent 不需要实现 RTL，但必须让后续软件和硬件可以复现这个近似。

## 7. 权重导出

请提供稳定的权重导出格式。建议至少输出：

~~~
层名称
张量形状
元素顺序
元素位宽
符号表示
字节序
Q 格式
偏置位置
校验和
~~~

如果最终编译进 RV32I 镜像，最好同时生成：

~~~
C 头文件或 C 源文件
一维连续数组
每个张量的长度和形状常量
~~~

矩阵排列方式需要记录清楚。行主序、列主序、按输出通道排列和按输入通道排列会直接影响后续矩阵乘加结果。

## 8. Golden 结果

请为每个固定测试向量生成主机端 golden 结果。建议同时保存：

~~~
浮点模型输出
定点模型输出
量化后的中间结果或关键层结果
最终分类结果
允许误差或等价判断规则
~~~

至少需要有以下小向量，方便逐层定位：

~~~
单步输入
一段短序列
全零输入
最大/最小输入
边界值输入
一组实际心电片段
~~~

后续 RV32I 软件和硬件加速器都应先通过这些小向量，再运行完整模型。

## 9. 资源和性能说明

请估算：

~~~
权重总字节数
中间激活最大字节数
单次推理需要的乘加次数
加法、比较和激活函数次数
最大临时缓冲区
单次推理的目标延迟
是否需要分块计算
~~~

当前 NPC 主存和最终 FPGA BRAM 容量还没有完全冻结，因此请提供不同配置下的资源表，例如小模型和完整模型。不要只报告参数数量，也要报告实际存储字节数和中间缓冲区大小。

## 10. 建议交付物

训练阶段完成后，请交付：

1. 浮点模型定义和推理脚本。
2. 固定点模型定义和推理脚本。
3. 量化参数和每层 Q 格式。
4. 权重导出脚本。
5. C 数组或可转换的权重文件。
6. 输入测试向量。
7. 浮点和定点 golden 输出。
8. 定点误差统计。
9. 模型参数量、权重大小和中间内存估算。
10. 一份简短的推理接口说明。

推理接口至少说明：

~~~
输入数组的类型和长度
输出数组的类型和长度
调用一次推理需要哪些状态
是否支持连续窗口
状态是否可以复用
~~~

## 11. 暂时不需要交付的内容

训练 agent 当前不需要负责：

- Wishbone 信号和时序；
- UART、GPIO、timer 地址；
- ADC RTL；
- FIFO 或 BRAM RTL；
- 加速器控制寄存器；
- DMA；
- CPU 中断；
- Verilator runner；
- NEMU DiffTest；
- AM 启动代码；
- FPGA 厂商 IP 工程。

这些由后续软件部署、RTL 和仿真 agent 根据模型交付物继续完成。

## 12. 当前建议流程

推荐流程：

~~~
先确定浮点模型
-> 导出固定测试向量和浮点 golden
-> 确定定点格式
-> 实现主机端定点模型
-> 比较浮点与定点误差
-> 导出权重和 C 数组
-> 评估 RV32I 软件实现的内存和计算量
-> 再决定哪些矩阵运算交给硬件加速器
~~~

训练阶段不要提前依赖 0x40000000 等硬件地址，也不要假定加速器一定支持某种矩阵布局。先把模型的数学和数据格式固定下来，硬件接口随后围绕这些结果设计。

## 13. 当前已确定的首版实验方案（2026-10-14）

以下选择用于启动第一轮可复现实验。后续可以根据验证集结果调整，但调整
必须记录版本号，不能混用不同预处理得到的结果。

- 数据集：MIT-BIH Arrhythmia Database，使用 `atr` beat annotations，采样率
  360 Hz，优先使用 MLII 导联；如果记录没有 MLII 才使用第二导联并记录下来。
- 任务：先做二分类。类别 0 为 AAMI `N`（`N/L/R/e/j`），类别 1 为
  `S/V/F`（`A/a/J/S/V/E/F`）。`Q`（`P/f/Q`）以及无法归类的标注全部排除，
  不把 paced/unknown 当作“异常”。五分类 `N/S/V/F/Q` 放在二分类基线之后。
- 样本：以每个标注的 R 峰为中心截取 256 点，前后各 128 点；靠近记录边界、
  无法取满窗口的标注丢弃。一次 LSTM 调用处理一个窗口，连续演示由上层逐拍调用。
- 输入预处理：WFDB 按 header 转换到物理单位后，使用训练记录统计的全局均值
  和标准差做标准化，并裁剪到 `[-5, 5]`；统计量保存为 JSON，推理端使用相同
  常数。最终 ADC 满量程确定后再冻结物理量和定点比例。
- 划分：按记录/患者划分，禁止随机拆分单个心拍。固定训练、验证、测试记录清单；
  记录 201 与 202 属于同一患者，必须放在同一 split。测试集只在模型和阈值确定后使用。
- 模型基线：单层、单向 LSTM，输入维度 1，隐藏维度比较 8/16，最后一个时间步
  接线性二分类头；从零训练。先保留浮点模型和 golden 输出，再做定点化。
- 评价：报告每类 precision/recall/F1、混淆矩阵和 macro-F1；不只报告 accuracy，
  因为 MIT-BIH 的类别分布严重不平衡。

首轮训练会生成实际的记录清单、样本数和验证结果；这些文件放在被 `.gitignore`
忽略的 `data/` 与 `artifacts/` 下，并随实验配置保存。
